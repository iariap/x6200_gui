## Sintoma

El fix de contraste del medidor del tema **RS** (`26dc5ec`, *"WCAG compliance 9/9 ... fix RS hallado y aplicado"*) **no se ve en la radio**: el medidor sigue dibujandose con el color viejo y, aun con el nuevo, el contraste real queda por debajo de 3:1.

## Medido en la radio (tema RS, JSON sincronizado y GUI reiniciada)

Muestreando los pixeles del arco del medidor en la captura del equipo:

```
pixeles rojos: 343 del color (255, 64, 64) = #ff4040   <- el color VIEJO
contraste contra el fondo real medido (62, 78, 92): 2.42:1   <- WCAG 1.4.11 pide 3:1
```

## Por que no llega (codigo)

- **RS es un tema de ROM**: `src/theme.c:31` dice *"Los temas que vienen con la ROM (Holo, Material 3 y RS, con sus imagenes)"*, y el color sale de la tabla compilada en `src/theme.h:129`:
  `X(meter_over, 0xffffff, 0xffffff, 0x000000, 0xff4040)`.
- Los `theme.json` se leen de **`/mnt/themes/`** y son para temas **custom** (`src/theme.c:4`: *"built-in tables and JSON files in /mnt/themes/"*), no para los de ROM.

Cambiar `rootfs/usr/share/x6200/themes/RS/theme.json` no afecta lo que el equipo dibuja.

## Y el valor nuevo no alcanza 3:1 con el fondo real

| Color | vs fondo real (62,78,92) | vs `colors.panel` del JSON (#000000) |
|---|---|---|
| `#ff4040` (viejo) | **2,47:1** *(no pasa)* | 5,3:1 *(pasa)* |
| `#ff5252` (nuevo) | **2,69:1** *(no pasa)* | 5,8:1 *(pasa)* |

El 9/9 del arnes se mide contra el `panel` declarado en el JSON (`#000000`), pero en pantalla el medidor se dibuja sobre otro fondo (barra/imagen). Con el valor nuevo el contraste seguiria por debajo de 3:1 **en el equipo**.

## Como reproducir

1. Poner el tema RS (`theme_name = RS`) en la radio.
2. Capturar y muestrear los pixeles del arco del medidor: sale `#ff4040`.
3. Calcular el contraste contra el fondo medido: 2,42:1 (y 2,69:1 con `#ff5252`).

Entorno: `x6200_gui` md5 `7f2c94ecb2c7` (rama `lu2dsx/x6200-rom`), kernel `Linux X6200 6.1.82 #2 SMP PREEMPT`.

## Que haria falta

1. Aplicar el color en la **tabla compilada** (`src/theme.h` / `THEME_COLORS`) o mover RS a JSON servido desde donde el firmware lo lee.
2. Elegir el valor midiendo contra el **fondo real** del medidor (no contra `panel = #000000`): con `(62,78,92)`, ni `#ff4040` ni `#ff5252` llegan a 3:1.

Evidencia: `docs/evidencia/2026-10-14-validacion-rs/` (captura + mediciones).
